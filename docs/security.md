# Threat model

AI input, project content, commands and MCP network requests are untrusted. The local OS user, dashboard user, Docker daemon, installed provider CLIs and sandbox image are trusted. The protection boundary is token authentication → intersected policy → container isolation → selected workspace.

## Controls

Loopback binding; separate UI/MCP ports; management Host and Origin allowlists; random per-run CSRF header; no management CORS; public dashboard proxy requires a separate owner session; OAuth routes allow standard discovery/token CORS; strict body sizes; CSP; token hashes and one-time display; revocation and expiration checked at each request and while jobs run; bounded jobs and output; container memory/CPU/process limits; forced container destruction; audit without command stdout/stderr; safe native argument-array subprocess calls; canonical workspace validation; no system root, home, config directory, devices or Docker socket workspace; absolute symlink root rejection; no host command execution from agent tools.

The running MCP Code installation and directories containing it cannot be selected as workspaces; otherwise an AI could rewrite the trusted dashboard or host-executed application code. To work on MCP Code itself, run a separately installed copy and share a source checkout. Workspace mounts necessarily reveal everything inside the selected folder. Users must exclude secrets from that folder. Files committed to the workspace, including .git/config/hooks, are untrusted and execute only inside containers. Read-only tokens never receive arbitrary shell execution. Tools return /workspace paths, never the host path. Environment variables are a fixed allowlist, with no inherited host secrets. Audit stores commands, which themselves can contain secrets; the UI explains this and supports clearing and retention.

## Assumptions and limits

Containers share the Docker engine's Linux kernel. A native Linux engine shares its host kernel; Docker Desktop runs its engine in a Linux VM, but containers are not individually isolated VMs. A patched Docker engine and OS are required; Docker rootless is recommended where available. Linux bind mounts expose the selected tree including user-created nested mount points; do not select directories containing additional host mounts. The daemon rejects sensitive roots and special files at workspace validation. The container cannot access host paths through symlinks, but symlinks may read other files within the same workspace. No concurrent malicious local administrator is defended against. Network enabled grants outbound access including reachable local-network services; do not enable it for untrusted clients. Read-only structured tools can still disclose repository secrets. Symlinked workspace roots and user-created symlink/junction parents are rejected rather than silently followed. Exact built-in macOS system aliases are validated against their canonical targets. Windows path comparisons account for case-insensitive drive paths.

The terminal policy deliberately denies execution unless read/write/execute/Git are all allowed; command-string filtering is not a permission boundary. Approval mode asks for every terminal command, rather than guessing which shell strings are destructive. Approval requests expire after two minutes and are cancelled on lifecycle changes. Synchronous commands are cancelled when their request disconnects. Explicit HTTP background jobs persist until cancelled, revoked, or timed out; stateless HTTP has no persistent transport session to observe. The stdio bridge cancels its background jobs on stdin closure. The UI does not show a selective deletion/install toggle that could be bypassed.

Bearer tokens must be entered only into clients supporting custom Authorization headers. OAuth uses PKCE S256, exact resource binding, registered callbacks, one-time 60-second authorization codes, one-hour access tokens and rotating refresh tokens with a fixed 30-day lifetime. Workspace checkboxes start unchecked; consent snapshots cap per-workspace permissions. Current policy is intersected at execution, and new workspaces or broader permissions require a new grant. Tunnel credentials stay with native provider configuration: Cloudflare quick tunnels need none; ngrok uses its native authtoken configuration. ngrok HTTP inspection is disabled, and provider log contents are not shown or persisted. HTTPS is provided by the provider. The authorization server runs locally; MCP Code owns no hosted relay, cloud database or cloud authentication service. Third-party AI and tunnel providers can process the data you send through them.

Report vulnerabilities privately to the repository maintainer before public disclosure. No maintainer contact is invented in this initial source distribution.

Remote owner login uses a random one-time code generated through the local dashboard. Codes expire after five minutes; sessions expire after eight hours and are stored only in memory as hashes, bound to the tunnel origin. Cookies are Secure, HttpOnly and SameSite=Lax. Public API requests require both owner session and the existing per-run CSRF header. Agent access tokens never authenticate management routes. Unknown or expired owner sessions cannot read the CSRF bootstrap. Disabling MCP leaves the owner dashboard available; stopping the tunnel or daemon removes public reachability. OAuth approvals are pending requests, not authority: the authenticated owner must choose projects and approve. Client display names are self-reported and are not proof of identity.
